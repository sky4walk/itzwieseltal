    Was ist das?

    Die RDP-Werkbank ist ein Remote-Desktop-Client, der komplett in dieser einen HTML-Datei steckt: TLS 1.2, MCS/GCC, Lizenzierung, Fähigkeiten-Austausch, Bilddecoder und Eingabe sind in JavaScript geschrieben. Weil ein Browser keine rohen TCP-Verbindungen öffnen darf, reicht eine kleine Python-Brücke die Bytes zwischen WebSocket und Port 3389 durch. Die Brücke sieht nur verschlüsselten Verkehr – entschlüsselt wird erst hier im Browser.

    Eingabe / Bild Fast-Path-Updates, Interleaved-RLE, Planar, ZeigerMS-RDPBCGR / MS-RDPEGDI
    RDP Client Info, Lizenz, Demand/Confirm Active, Share DataMS-RDPBCGR, MS-RDPELE
    MCS / GCC Connect Initial (BER), Domain-PDUs (PER), KanäleT.125 / T.124
    TLS 1.2 ECDHE + AES-GCM über WebCryptoRFC 5246, 5288, 8422
    X.224 / TPKT Verbindungsaufbau, ProtokollwahlRFC 1006, X.224
    WebSocket → Brücke → TCP 3389rdpbridge.py

    Brücke starten

    rdpbridge.py steckt in dieser Seite und braucht nur Python 3 ohne Zusatzpakete – ideal für den Raspi im Netz.

    

    python3 rdpbridge.py --allow 192.168.178.0/24
# nur bestimmte Origins zulassen:
python3 rdpbridge.py --allow 192.168.178.20 --origin https://sky4walk.github.io
# Seite direkt von der Brücke ausliefern (dann reicht ws://):
python3 rdpbridge.py --html rdpwerk.html      → http://raspi:8765/
    

    Mixed Content: Wird diese Seite per https:// geöffnet (z. B. von GitHub Pages), erlaubt der Browser nur wss:// – außer zu localhost. Möglichkeiten: Brücke auf dem eigenen Rechner (ws://localhost:8765), Brücke mit --cert/--key als wss:// (Zertifikat einmal im Browser unter https://raspi:8765 akzeptieren) oder Seite über --html von der Brücke laden. Chrome fragt beim Zugriff einer öffentlichen Seite aufs Heimnetz zusätzlich nach der Berechtigung „Lokales Netzwerk“.
    

    Sicherheit: Die Brücke nie ungeschützt ins Internet stellen – sie wäre ein offenes Tor zu jedem freigegebenen RDP-Server. Mit --allow die Ziele einschränken, von unterwegs nur über VPN oder Tunnel.
    

    Was Stufe 1 kann
    

      

    • TLS-Sicherheit (PROTOCOL_SSL), Autologon mit Passwort oder Anmeldung am Server-Bildschirm
      • 

    • Lizenzierung inkl. Platform Challenge (RC4/MD5) – xrdp, Windows-Desktop, Windows Server
      • 

    • Bitmaps: 15/16/24 Bit Interleaved-RLE, 32 Bit Planar, unkomprimiert, 8 Bit mit Palette
      • 

    • Farbige und große Mauszeiger, Fast-Path-Ein- und Ausgabe, Strg+Alt+Entf, Mausrad
      • 

    • Protokoll aller PDUs mit Hexdump, Statistik
      • 

    • Die Python-Brücke ist eingebettet – eine Datei für alles
      • 

    

    Was noch fehlt
    

      

    • NLA / CredSSP (Stufe 2): Windows 10/11 und Server verlangen das standardmäßig. Bis dahin am Server in Systemeigenschaften → Remote „Verbindungen nur von Computern zulassen, auf denen Remotedesktop mit Authentifizierung auf Netzwerkebene ausgeführt wird“ abschalten – oder gegen xrdp testen.
      • 

    • H.264 (AVC420/444) über WebCodecs, RemoteFX, Zwischenablage, Ton, Größenänderung (Stufe 3)
      • 

    • Zeichen-Orders und Bitmap-Caches – absichtlich abgeschaltet, der Server schickt dann alles als Bitmaps
      •
