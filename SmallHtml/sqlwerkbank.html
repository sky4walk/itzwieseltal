SQL-Referenz

Alles, was die SQL-Werkbank versteht – mit Beispielen, die du direkt ausführen kannst. Die Engine ist selbst geschrieben: Ein Lexer zerlegt den Text in Wörter, ein Parser baut daraus einen Syntaxbaum, und ein Interpreter arbeitet diesen Baum auf den Tabellen im Speicher ab.

1. Grundbegriffe

BegriffBedeutung
Tabelle (Relation)Sammlung gleichartiger Datensätze, z. B. alle Schüler. Jede Tabelle hat feste Spalten mit Namen und Datentyp.
Zeile (Datensatz, Tupel)Ein einzelner Eintrag, z. B. ein Schüler.
Spalte (Attribut)Eine Eigenschaft, z. B. nachname. In einer Zelle steht genau ein Wert – oder NULL (kein Wert).
Primärschlüssel (PRIMARY KEY)Spalte(n), die jede Zeile eindeutig kennzeichnen, z. B. id. Darf weder doppelt noch NULL sein.
Fremdschlüssel (FOREIGN KEY)Spalte, die auf den Primärschlüssel einer anderen Tabelle verweist, z. B. noten.schueler_id → schueler.id. Die Datenbank sorgt dafür, dass es den Verweis wirklich gibt (referenzielle Integrität).
Beziehung 1 : nEin Schüler hat viele Noten, eine Note gehört zu genau einem Schüler. Im ER-Diagramm (Reiter „Datenbank“) als Linie mit „1“ und „n“.
Beziehung n : mEin Rezept hat viele Rohstoffe, ein Rohstoff steckt in vielen Rezepten. Braucht eine Zwischentabelle (hier: zutaten) mit zwei Fremdschlüsseln.

SQL gliedert sich in drei Teile: DQL (Daten abfragen: SELECT), DML (Daten ändern: INSERT, UPDATE, DELETE) und DDL (Struktur festlegen: CREATE, ALTER, DROP). Groß-/Kleinschreibung spielt bei Befehlen und Namen keine Rolle, bei Texten in Anführungszeichen schon. Mehrere Anweisungen trennt man mit ;. Kommentare beginnen mit -- oder stehen zwischen /* … */.

2. SELECT – Aufbau und Reihenfolge

SELECT   klasse, COUNT(*) AS anzahl     -- welche Spalten?
FROM     schueler                       -- aus welcher Tabelle?
WHERE    wohnort = 'Schwabach'          -- welche Zeilen?
GROUP BY klasse                         -- wie zusammenfassen?
HAVING   COUNT(*) >= 3                  -- welche Gruppen?
ORDER BY anzahl DESC                    -- wie sortieren?
LIMIT    3;                             -- wie viele?

Geschrieben wird in dieser Reihenfolge – ausgeführt aber in einer anderen. Das erklärt viele Fehlermeldungen: Ein Alias aus SELECT ist in WHERE noch unbekannt, weil WHERE vorher drankommt.

1FROM / JOIN→2WHERE→3GROUP BY→4HAVING→5SELECT→6DISTINCT→7ORDER BY→8LIMIT
Schalte im Editor Schritt für Schritt ein: Dann zeigt jede SELECT-Abfrage Reiter für alle Zwischenergebnisse – du siehst, welche Zeilen nach FROM da sind, welche WHERE übrig lässt, wie GROUP BY sie zu Gruppen bündelt (farbig markiert) und so weiter. EXPLAIN SELECT … zeigt den Ausführungsplan als Text.
SchreibweiseWirkung
SELECT *alle Spalten
SELECT a, b AS neubestimmte Spalten, b umbenannt (Alias)
SELECT DISTINCT ortdoppelte Ergebniszeilen entfernen
ORDER BY a DESC, bnach a absteigend, bei Gleichstand nach b aufsteigend (ASC). Auch ORDER BY 2 (2. Spalte) oder Aliasnamen sind erlaubt; NULLS FIRST/LAST legt fest, wohin leere Werte kommen.
LIMIT 10 OFFSET 2010 Zeilen ab der 21. – zum „Blättern“. Auch LIMIT 20, 10, SELECT TOP 10 und FETCH FIRST 10 ROWS ONLY werden verstanden.

NULL – der fehlende Wert

NULL heißt „unbekannt“. Jeder Vergleich mit NULL ergibt wieder unbekannt – auch NULL = NULL! WHERE lässt nur Zeilen durch, deren Bedingung wahr ist. Deshalb findet WHERE email = NULL nie etwas; richtig ist WHERE email IS NULL. SQL rechnet mit dreiwertiger Logik: TRUE AND NULL ist NULL, FALSE AND NULL ist FALSE, TRUE OR NULL ist TRUE.

SELECT NULL = NULL      AS gleich,
       NULL IS NULL     AS ist_null,
       1 + NULL         AS summe,
       TRUE AND NULL    AS und,
       COALESCE(NULL, 'Ersatz') AS ersatz;
Falle mit NOT IN: Liefert die Unterabfrage bei x NOT IN (SELECT …) auch nur einen NULL-Wert, ist das Ergebnis immer leer. Abhilfe: in der Unterabfrage WHERE spalte IS NOT NULL ergänzen oder NOT EXISTS verwenden.

4. Rechnen, Texte und Fallunterscheidungen

In SELECT (und überall sonst) kann man rechnen: + - * /, % bzw. MOD (Rest) und DIV (ganzzahlige Division). Texte verbindet man mit || oder CONCAT(…). CASE wählt je nach Bedingung einen Wert aus.

SELECT name,
       preis,
       ROUND(preis * 1.19, 2)      AS brutto,
       name || ' (' || preis || ' €)' AS etikett,
       CASE WHEN preis < 10  THEN 'günstig'
            WHEN preis < 50  THEN 'mittel'
            ELSE 'teuer' END       AS preisklasse
FROM produkte
ORDER BY preis;

5. Aggregatfunktionen und GROUP BY

Aggregatfunktionen fassen viele Zeilen zu einem Wert zusammen: COUNT(*) (Anzahl Zeilen), COUNT(spalte) (Anzahl Werte ≠ NULL), COUNT(DISTINCT spalte), SUM, AVG, MIN, MAX und GROUP_CONCAT(spalte, ', ') bzw. STRING_AGG. NULL-Werte werden dabei übersprungen.

Mit GROUP BY entsteht pro unterschiedlichem Wert eine Gruppe, und die Aggregatfunktion wird für jede Gruppe einzeln berechnet. HAVING filtert anschließend ganze Gruppen – WHERE dagegen filtert vorher einzelne Zeilen.

SELECT fach,
       COUNT(*)              AS anzahl,
       ROUND(AVG(note), 2)   AS schnitt,
       MIN(note)             AS beste,
       MAX(note)             AS schlechteste
FROM noten
WHERE art = 'Schulaufgabe'
GROUP BY fach
HAVING COUNT(*) > 10
ORDER BY schnitt;
Die GROUP-BY-Regel: Wird gruppiert, dürfen in SELECT, HAVING und ORDER BY nur Spalten stehen, die auch in GROUP BY vorkommen – alles andere muss in einer Aggregatfunktion stecken. SELECT nachname, COUNT(*) FROM schueler GROUP BY klasse ist falsch: Welcher der vielen Nachnamen einer Klasse sollte angezeigt werden? Die SQL-Werkbank prüft das so streng wie PostgreSQL (MySQL und SQLite liefern hier stillschweigend irgendeinen Wert).

6. Tabellen verbinden – JOIN

Ein JOIN verknüpft zu jeder Zeile der einen Tabelle die passenden Zeilen der anderen. Die Bedingung steht nach ON; meistens ist es „Fremdschlüssel = Primärschlüssel“. Mit kurzen Aliasen (schueler s) bleibt die Abfrage lesbar.

SELECT s.vorname, s.nachname, f.name AS fach, n.note
FROM noten n
JOIN schueler s ON s.id = n.schueler_id
JOIN faecher  f ON f.kuerzel = n.fach
WHERE s.klasse = '10a' AND n.art = 'Schulaufgabe'
ORDER BY s.nachname, f.name;

LEFT JOIN braucht man, wenn auch Zeilen ohne Partner erscheinen sollen – etwa Fächer, für die es keine Lehrkraft gibt, oder Kunden ohne Bestellung:

SELECT k.vorname, k.nachname, COUNT(b.id) AS bestellungen
FROM kunden k
LEFT JOIN bestellungen b ON b.kunde_id = k.id
GROUP BY k.id, k.vorname, k.nachname
ORDER BY bestellungen;
VarianteErklärung
CROSS JOIN bzw. FROM a, bKreuzprodukt: jede Zeile mit jeder. Mit einer WHERE-Bedingung ergibt sich wieder ein normaler Join (alte Schreibweise).
JOIN … USING (spalte)Kurzform, wenn die Spalte in beiden Tabellen gleich heißt.
NATURAL JOINverbindet automatisch über alle gleichnamigen Spalten – bequem, aber riskant.
Self-JoinEine Tabelle mit sich selbst verbinden, z. B. Mitarbeiter und ihre Chefs: FROM ma m JOIN ma c ON m.chef_id = c.id.
Für Gleichheitsbedingungen (a.x = b.y) benutzt die SQL-Werkbank intern einen Hash-Join: Sie baut für die rechte Tabelle ein Verzeichnis nach dem Schlüsselwert und muss so nicht jede Zeile mit jeder vergleichen. Andere Bedingungen werden mit einer verschachtelten Schleife (Nested Loop) geprüft.

7. Unterabfragen und WITH

Eine Abfrage in Klammern kann als Einzelwert, als Liste (bei IN), als Wahrheitswert (bei EXISTS) oder als Tabelle (in FROM) dienen. Bezieht sich die innere Abfrage auf eine Spalte der äußeren, heißt sie korreliert und wird für jede äußere Zeile neu berechnet.

-- Einzelwert: Sude mit mehr Litern als der Durchschnitt
SELECT id, braudatum, liter
FROM sude
WHERE liter > (SELECT AVG(liter) FROM sude);

-- korreliert mit EXISTS: Mitglieder, die schon einmal gebraut haben
SELECT vorname, nachname
FROM mitglieder m
WHERE EXISTS (SELECT 1 FROM sude s WHERE s.braumeister_id = m.id);

-- Unterabfrage als Tabelle + Vergleich mit ALL
SELECT name, preis FROM produkte
WHERE preis >= ALL (SELECT preis FROM produkte);

WITH name AS (…) gibt einer Unterabfrage einen Namen (Common Table Expression) – das macht lange Abfragen lesbarer. WITH RECURSIVE ruft sich selbst auf, bis keine neuen Zeilen mehr entstehen:

WITH schnitt AS (
  SELECT schueler_id, AVG(note) AS s FROM noten GROUP BY schueler_id
)
SELECT sc.vorname, sc.nachname, sc.klasse, ROUND(s, 2) AS schnitt
FROM schnitt JOIN schueler sc ON sc.id = schnitt.schueler_id
WHERE s < 2
ORDER BY s;

WITH RECURSIVE fib(n, a, b) AS (
  SELECT 1, 0, 1
  UNION ALL
  SELECT n + 1, b, a + b FROM fib WHERE n < 20
)
SELECT n, a AS fibonacci FROM fib;

8. Mengenoperationen

Zwei Abfragen mit gleich vielen Spalten lassen sich kombinieren: UNION (Vereinigung ohne Doppelte), UNION ALL (mit Doppelten), INTERSECT (Schnittmenge), EXCEPT (Differenz). Ein abschließendes ORDER BY gilt für das Gesamtergebnis.

SELECT vorname || ' ' || nachname AS person, 'Lehrkraft' AS rolle FROM lehrer
UNION
SELECT vorname || ' ' || nachname, 'Schüler/in' FROM schueler WHERE klasse = '10a'
ORDER BY rolle, person;

10. Tabellen anlegen – CREATE TABLE

CREATE TABLE autor (
  id        INTEGER PRIMARY KEY,
  name      VARCHAR(50) NOT NULL,
  land      VARCHAR(30) DEFAULT 'Deutschland'
);
CREATE TABLE buch (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  titel     VARCHAR(100) NOT NULL,
  isbn      VARCHAR(17) UNIQUE,
  seiten    INTEGER CHECK (seiten > 0),
  preis     DECIMAL(6,2),
  erschienen DATE,
  autor_id  INTEGER REFERENCES autor(id) ON DELETE CASCADE
);

11. Transaktionen

Mehrere Änderungen sollen oft „ganz oder gar nicht“ passieren – etwa eine Überweisung: abbuchen und gutschreiben. Nach BEGIN merkt sich die Datenbank den Ausgangszustand; COMMIT macht die Änderungen endgültig, ROLLBACK verwirft alles seit BEGIN. Solange eine Transaktion offen ist, steht das unten in der Statusleiste.

BEGIN;
DELETE FROM positionen;
SELECT COUNT(*) AS positionen_nach_delete FROM positionen;
ROLLBACK;
SELECT COUNT(*) AS positionen_nach_rollback FROM positionen;

Die vier Eigenschaften einer Transaktion merkt man sich als ACID: Atomicity (ganz oder gar nicht), Consistency (alle Bedingungen gelten danach wieder), Isolation (gleichzeitige Transaktionen stören sich nicht) und Durability (Bestätigtes bleibt erhalten). Die SQL-Werkbank hat nur einen Benutzer – Isolation spielt daher keine Rolle, und „dauerhaft“ heißt hier: bis du die Seite schließt.

13. Unterschiede zu „großen“ Datenbanksystemen

Die SQL-Werkbank orientiert sich am SQL-Standard und übernimmt bequeme Schreibweisen aus MySQL, SQLite und PostgreSQL. Ein paar Punkte, die man kennen sollte:

  • / rechnet immer mit Nachkommastellen (7 / 2 = 3.5, wie MySQL). Ganzzahlige Division: 7 DIV 2 = 3. Division durch 0 ergibt NULL.
  • Texte gehören in einfache Anführungszeichen '…'. Doppelte Anführungszeichen "…" kennzeichnen eigentlich Namen; gibt es keine solche Spalte, wird der Inhalt – wie bei SQLite – als Text behandelt.
  • = unterscheidet Groß-/Kleinschreibung, LIKE nicht. Sortiert wird nach deutscher Schreibweise (Ä bei A, ß bei ss).
  • Die GROUP-BY-Regel wird streng geprüft (wie PostgreSQL), Datentypen werden beim Einfügen geprüft (strenger als SQLite).
  • Nicht unterstützt: Fensterfunktionen (OVER), Trigger, gespeicherte Prozeduren, Benutzerrechte (GRANT), mehrere gleichzeitige Benutzer.
  • Alles liegt im Arbeitsspeicher des Browsers. Beim Schließen der Seite ist die Datenbank weg – vorher mit ⬇ DB-Export sichern.
