Warum eine Brücke?

Das alte Java-Applet hat direkt per TCP (Port 8889, bei alter Firmware 8888) mit dem Regler gesprochen. Browser dürfen das nicht – Java-Applets sind seit Jahren tot. Die kleine Brücke luxbridge.py (nur Python-Standardbibliothek) übersetzt dieses Binärprotokoll nach HTTP und liefert auch diese Seite aus.

Einrichtung

  1. IP-Adresse der Wärmepumpe herausfinden (Router-Oberfläche oder am Regler unter Service → Systemeinstellungen → TCP/IP).
  2. luxbridge.py (Reiter Brücke (Python)) und luxwerk.html in denselben Ordner legen.
  3. Starten: 
    python3 luxbridge.py 192.168.178.95
  4. Im Browser öffnen: http://localhost:8088/

Optionen

--port 8888          alter Regler-Port
--http 8088          Port der Brücke
--bind 0.0.0.0       auch von Handy/Tablet im Heimnetz erreichbar
--rec 30             Daueraufzeichnung für „Analyse“ alle 30 s (Standard, Ordner luxdata)
--data /pfad         anderer Datenordner, z. B. auf NAS oder USB-Laufwerk
--mount /mnt/nas     nur schreiben, wenn dieses Laufwerk eingehängt ist
--no-rec             keine Daueraufzeichnung
--log verlauf.csv    zusätzlich einfache CSV (--interval 60)
--expert             alle Parameter schreibbar (sonst nur Betriebsarten und Sollwerte)

Läuft gut dauerhaft auf einem Raspberry Pi oder NAS. Ohne --expert lässt die Brücke nur vier Parameter zu: Betriebsart Heizung, Betriebsart Warmwasser, Temperatur ± und Warmwasser-Soll – jeweils mit Bereichsprüfung.

Neuere Firmware

Ab Firmware V3.79 und höher bringt der Regler selbst eine Weboberfläche mit (http://IP-der-Wärmepumpe, Passwort ab Werk 999999). Die Firmware-Version steht hier auf der Übersicht. Das Binärprotokoll auf 8889 funktioniert bei beiden.

luxbridge.py

Die Brücke zwischen Browser und Regler. Neben luxwerk.html speichern und starten:

python3 luxbridge.py 192.168.178.95            # IP deines Reglers
python3 luxbridge.py 192.168.178.95 --port 8888   # falls 8889 nicht antwortet

  


  

    
Als Dienst auf dem Raspberry Pi (systemd)

    
So läuft die Brücke dauerhaft im Hintergrund und startet nach einem Stromausfall von selbst.


    
1 · Einrichten (einmalig)

    
Dateien vom PC auf den Pi kopieren (Name oder IP des Pi anpassen):

    
scp luxbridge.py luxwerk.html pi@raspberrypi.local:/tmp/

    
Auf dem Pi: Ordner und eigenen Benutzer ohne Rechte anlegen:

    
sudo mkdir -p /opt/luxwerk
sudo mv /tmp/luxbridge.py /tmp/luxwerk.html /opt/luxwerk/
sudo useradd -r -s /usr/sbin/nologin luxwerk
sudo chown -R luxwerk: /opt/luxwerk

    
Dienstdatei anlegen mit sudo nano /etc/systemd/system/luxwerk.service und diesen Inhalt einfügen
      (IP und Port des Reglers ggf. anpassen). Ohne NAS bzw. USB-Laufwerk die beiden Optionen --data und --mount weglassen,
      dann landet die Aufzeichnung in /opt/luxwerk/luxdata (siehe Abschnitt 5).

    

    

      alternativ: herunterladen und mit sudo cp luxwerk.service /etc/systemd/system/ einspielen

    
Dienst aktivieren und starten:

    
sudo systemctl daemon-reload
sudo systemctl enable --now luxwerk

    
Danach im Browser: http://<IP-des-Pi>:8088/


    
2 · Bedienen

    

      
systemctl status luxwerkLäuft er? Letzte Meldungen

      
journalctl -u luxwerk -fMeldungen live mitlesen (Ende mit Strg+C)

      
sudo systemctl stop luxwerkStoppen – läuft bis zum nächsten Neustart des Pi nicht mehr

      
sudo systemctl start luxwerkWieder starten

      
sudo systemctl restart luxwerkNeu starten, z. B. nach neuer luxbridge.py oder geänderter Dienstdatei

      
sudo systemctl disable --now luxwerkDauerhaft stoppen – startet auch beim Hochfahren nicht mehr

      
sudo systemctl enable --now luxwerkDauerhaft wieder einschalten

    

    
Nach Änderungen an luxwerk.service immer zuerst sudo systemctl daemon-reload, dann restart.
      Eine neue luxwerk.html braucht keinen Neustart – einfach nach /opt/luxwerk/ kopieren und die Seite neu laden.


    
3 · Aktualisieren

    
scp luxbridge.py luxwerk.html pi@raspberrypi.local:/tmp/
sudo mv /tmp/luxbridge.py /tmp/luxwerk.html /opt/luxwerk/
sudo chown luxwerk: /opt/luxwerk/*
sudo systemctl restart luxwerk


    
4 · Komplett entfernen

    
sudo systemctl disable --now luxwerk
sudo rm /etc/systemd/system/luxwerk.service
sudo systemctl daemon-reload
sudo rm -r /opt/luxwerk        # löscht auch die Aufzeichnung in luxdata! (auf dem NAS bleibt sie liegen)
sudo userdel luxwerk


    
5 · Aufzeichnung auf NAS oder USB-Laufwerk (SD-Karte schonen)

    
Die Daueraufzeichnung schreibt alle 30 s eine Zeile. Über Wochen und Monate ist das für die SD-Karte des Pi unnötige Last.
      Mit --data legt die Brücke ihre Daten auf ein eingehängtes Laufwerk, --mount nennt dessen Einhängepunkt.

    
Warum --mount? Ist das Laufwerk nicht eingehängt (NAS aus, Netzwerk weg, USB-Stick abgezogen),
      ist /mnt/nas nur ein leerer Ordner auf der SD-Karte, und die Brücke würde unbemerkt wieder dorthin schreiben.
      Mit --mount pausiert sie stattdessen die Aufzeichnung und meldet das einmal im Journal. Live-Anzeige und Bedienen laufen weiter.
      Sobald das Laufwerk wieder da ist, schreibt sie von selbst weiter. Der Datenordner muss unterhalb von --mount liegen.

    
Beispiel /etc/fstab für eine Windows/Samba-Freigabe (FRITZ!Box-NAS, Synology …).
      Wichtig ist uid/gid, damit der Dienstbenutzer luxwerk schreiben darf:

    
//192.168.178.10/daten  /mnt/nas  cifs  credentials=/etc/nas-cred,uid=luxwerk,gid=luxwerk,iocharset=utf8,_netdev,nofail,x-systemd.automount  0  0

    
/etc/nas-cred enthält zwei Zeilen username=… und password=… (danach sudo chmod 600 /etc/nas-cred).
      Für NFS sieht die Zeile so aus; dort muss der Ordner auf dem NAS der UID von luxwerk gehören (id luxwerk zeigt sie):

    
192.168.178.10:/volume1/daten  /mnt/nas  nfs  _netdev,nofail,x-systemd.automount  0  0

    
Einrichten, vorhandene Aufzeichnung umziehen, Dienst neu starten:

    
sudo mkdir -p /mnt/nas
sudo systemctl daemon-reload
sudo mount /mnt/nas
sudo -u luxwerk mkdir -p /mnt/nas/luxdata          # testet zugleich das Schreibrecht
sudo systemctl stop luxwerk
sudo cp -a /opt/luxwerk/luxdata/. /mnt/nas/luxdata/
sudo nano /etc/systemd/system/luxwerk.service     # ExecStart: --data /mnt/nas/luxdata --mount /mnt/nas
sudo systemctl daemon-reload
sudo systemctl start luxwerk
journalctl -u luxwerk -n 20                       # zeigt „Daueraufzeichnung … nach /mnt/nas/luxdata“

    
Den Ordner /opt/luxwerk/luxdata danach löschen, sobald die Analyse mit den Daten auf dem NAS funktioniert.
      Im Reiter „Analyse“ steht hinter der Zahl der Messpunkte, aus welchem Ordner gelesen wurde.


    
Sicherheit: Die Brücke hat keinen Passwortschutz. Port 8088 nicht in der FRITZ!Box nach außen freigeben – für unterwegs das VPN der FRITZ!Box nutzen.
      Wer im Dienst --expert ergänzt, erlaubt allen im Heimnetz, jeden Parameter zu schreiben; besser nur vorübergehend.
